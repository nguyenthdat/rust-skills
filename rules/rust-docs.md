# Rust: documentation comments (Google Rust Style Guide)

- **Document public APIs** with `///`; the `missing_docs` lint can enforce it. Module and crate docs use `//!` at the top of the file. Enum variants with self-explanatory names may stay undocumented.
- **Say what the code does not say.** Never restate the name (`/// Removes an element.` on `remove_element`) and never explain the language (`/// A mock implementation of the FileSystem trait…` above `impl FileSystem for MockFileSystem`). With nothing insightful to add, omit the comment.
- **Required sections**: document the panic conditions of any function that can panic on malformed input (`# Panics`), and the invariants of every `unsafe fn` and `unsafe trait` (`# Safety`). Add `# Examples` where they show how the crate is used; not every function needs one.
- **Write full sentences** with capitalization and punctuation, in Markdown, following the official Rust doc-comment style.
- **Write docs in plain `///` and `//!` comments**, not `/** */`, `/*! */`, or `#[doc = "…"]` generated by macros. `#[doc = include_str!("../README.md")]` is fine.
- **Implementation notes, TODOs, and commented-out code use `//`.** Mixing is encouraged: `///` for the public contract, with a `//` note right below it for the implementation.

If the doc comments you wrote already follow these rules, move on.
